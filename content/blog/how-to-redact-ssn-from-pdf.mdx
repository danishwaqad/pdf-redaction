## Quick answer

To **redact an SSN from a PDF** permanently, use a redaction tool that deletes extractable text — not a black shape in Edge, Word, or a generic PDF editor. Run **PII detect** and **manual search** for every format the number might take (`123-45-6789`, no dashes, spaced, in tables). After Apply, **search the output file** — if Ctrl+F still finds the SSN, you are not done.

## Why SSN redaction fails in real cases

A discovery coordinator described production week: opposing counsel returned a PDF with black rectangles over Social Security numbers. A junior associate searched the file in thirty seconds and produced a spreadsheet of every "redacted" SSN. The issue was not malice — it was **overlay markup** instead of removal. That pattern drives sanctions, do-overs, and breach notifications.

Common failure modes:

- **Visual blackout only** — SSN remains in the PDF content stream ([why blacking out fails](/blog/why-blacking-out-pdf-is-not-safe))
- **Page-one-only redaction** — SSN repeats in headers on pages 2–40
- **Partial masking** — last four digits plus name and date of birth can still identify someone
- **OCR layer left behind** on scans — image looks redacted; invisible text survives ([scanned PDF guide](/blog/how-to-redact-scanned-pdf-ocr))
- **Filename leak** — `Smith_SSN_123456789.pdf` in the path or metadata

## Step-by-step: remove Social Security number from PDF

### 1. Open and inventory

Upload to [RedactPDF](/tool). Note every place SSNs appear: body text, tables, headers, footers, exhibits, cover sheets, and comment annotations if your viewer exports them.

### 2. Auto-detect + search

Run **PII detect** for SSN-style patterns. Then search manually for variants:

- `###-##-####` (standard)
- Nine digits without dashes
- Spaced groups (`123 45 6789`)
- Rows in tables where digits split across cells — box the **entire row**, not one cell

Auto-detect is a first pass. **Never ship without a human scroll.**

### 3. Pair SSN with context

Regulators and courts care about combinations. If you leave full name + date of birth on the same line as a masked SSN, re-identification may still be possible. When in doubt, redact the wider region and let counsel decide on the privilege log.

### 4. Apply and verify on the output

Download the redacted PDF. On that file only:

| Test | Pass |
|------|------|
| Search all SSN formats you know appear in the source | Zero hits |
| Select + paste entire document | No SSN strings |
| Second reviewer independent search | Agrees pass |
| Rename file if SSN was in the filename | Clean name |

## Redaction vs masking vs pseudonymization

**Redaction** removes the value from the distributed file — irreversible in that copy.

**Masking** (`XXX-XX-1234`) may still support identification when combined with other fields.

**Pseudonymization** replaces SSN with a token; a separate mapping table must stay secured.

Your counsel picks the approach; this guide assumes **redaction for outward-facing PDFs**.

## Mistakes that create liability

Filing the **unredacted** version by email autofill error — always open the attachment you are about to send.

Redacting the SSN but leaving **email + full name + employer** when policy required broader removal.

Privilege log entries that do not match Bates ranges after re-redaction.

Skipping verification because "we always use the same tool."
