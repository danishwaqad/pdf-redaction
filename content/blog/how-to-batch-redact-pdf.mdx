## The repeatable batch workflow (100 files)

### Phase 1 — Prepare (30 min once)

| Step | Action |
|------|--------|
| 1 | Create folder: `source/` and `redacted/` |
| 2 | Write **redaction rules** doc: what to remove (SSN, account #, etc.) |
| 3 | Name convention: `ORIGINAL_v1.pdf` → `REDACTED_v1.pdf` |
| 4 | Bookmark [RedactPDF](/tool) in browser |

### Phase 2 — Process each file (~3–8 min/file)

| Step | Action |
|------|--------|
| 1 | Open RedactPDF → upload next PDF from `source/` |
| 2 | Run **PII detect** + **search** for matter-specific strings |
| 3 | Manual pass — headers, footers, exhibits |
| 4 | Apply → save to `redacted/` with certificate |
| 5 | **Verify** — search one known string per file |
| 6 | Log in spreadsheet: filename, date, operator, pass/fail |

### Phase 3 — QA sample (10%)

| Sample size | Action |
|-------------|--------|
| 100 files | Fully re-verify 10 random outputs |
| Any fail | Re-process failed file + adjacent same-type files |

## Speed tips without skipping security

| Tip | Time saved |
|-----|------------|
| Same redaction rules per doc type | Less decision fatigue |
| PII detect first pass | Catches 60–80% of structured data |
| Search template list (SSN, @, phone patterns) | Faster than manual scan |
| Dual monitors — rules on screen 2 | Fewer mistakes |
| Keyboard shortcuts browser back | Faster reload between files |

**Never skip verification** — one leaked SSN in batch 100 costs more than all saved minutes.
